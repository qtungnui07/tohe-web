## Context
Jenkins đang chạy được tới stage `Lint` nhưng pipeline dừng với `1 error` và `5 warnings`; stage `Build` bị bỏ qua. Jenkinsfile hiện gọi `npm ci`, `npm run lint`, rồi `npm run build`. Log ảnh cho thấy ít nhất cảnh báo `<img>` tại `app/page.tsx:112`, nhưng phần chứa lỗi chính nằm phía trên ảnh nên cần tái hiện từ repo để sửa đúng nguyên nhân thay vì che lỗi trong Jenkins.

## Cách xử lý đề xuất
1. Tái hiện CI bằng các lệnh trong `Jenkinsfile` và đọc đầy đủ output ESLint/TypeScript, đồng thời kiểm tra lockfile và phiên bản Node/npm mà pipeline cần.
2. Sửa lỗi lint thực sự trong các file được ESLint báo; xử lý các cảnh báo liên quan đến ảnh theo chuẩn Next hiện tại (ưu tiên thay `<img>` bằng `next/image` nếu phù hợp với layout/nguồn ảnh, hoặc cấu hình ngoại lệ có chủ đích nếu ảnh là resource động). Không hạ tiêu chuẩn lint hay bỏ qua stage để “làm xanh” pipeline.
3. Kiểm tra `Jenkinsfile` và cách cài dependency cho nhất quán với lockfile hiện có; chỉ chỉnh pipeline nếu việc dùng `npm ci` không khớp với repository hoặc môi trường Jenkins.
4. Chạy lại `npm run lint` và `npm run build`; nếu có test/typecheck hiện hữu thì chạy thêm, rồi kiểm tra diff để bảo đảm không ảnh hưởng UI/runtime.

## File trọng tâm
- `Jenkinsfile` — chuỗi stage CI hiện tại.
- `package.json` và lockfile — scripts, dependency và trình quản lý package.
- `eslint.config.mjs` — quy tắc lint đang áp dụng.
- `app/page.tsx` cùng các file được ESLint chỉ ra — nguồn lỗi/cảnh báo cần sửa.

## Xác minh
- Lint kết thúc exit code 0.
- Build production kết thúc thành công.
- Jenkins có thể chạy đủ các stage `Checkout → Install Dependencies → Lint → Build`, không còn bị skip do lỗi trước đó.
- Báo cáo cuối sẽ nêu rõ các file đã sửa và kết quả từng lệnh kiểm tra.
